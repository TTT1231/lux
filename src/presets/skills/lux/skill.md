## fmt — generate lint/format configs

```bash
lux fmt <preset> [--stylelint] [--editorconfig] [--cspell] [--husky] [--lint-staged]
lux fmt list
```

built-in presets: `web-vue` `web-react` `electron-vue` `uniapp` `node` `nest`

### Opt-in flags

Only ESLint + Prettier are generated by default. Add flags to include additional tools:

- `--stylelint` — generate stylelint config + deps + scripts
- `--editorconfig` — generate .editorconfig + deps
- `--cspell` — generate cspell.json + deps + scripts
- `--husky` — initialize husky for Git hooks (creates `.husky/_` support files and `.husky/pre-commit`, injects init script)
- `--lint-staged` — generate `.lintstagedrc.json` + deps + scripts (implies `--husky`)

Each flag controls three layers of filtering — **files** (exact filename), **deps** (tool-key lookup), **script keys** (case-sensitive exact `:` segment match). See `references/custom-preset-setting.md` for details.

### Control flags

- `--force` — overwrite existing config files, package.json scripts, config-family sibling detection, and `.husky/pre-commit`. Default behavior skips existing files/scripts/hooks and skips generation when a sibling config exists (for example `eslint.config.js` when generating `eslint.config.mjs`). `--force` does not affect deps — deps are always additive (missing only, no version overwrite).
- `--dry-run` — preview mode, write nothing. Outputs `[dry-run]` prefixed messages showing what would happen.
- `--no-install` — write deps to package.json but **skip** `bun/npm install`. Useful for CI or manual install control.
- `--reset` — reset local preset. For built-in presets: deletes `~/.lux/preset/fmt/<name>/` and re-materializes from built-in template. For custom presets: **aborts immediately** with a warning (no built-in source to restore).

### list

`lux fmt list` — Built-in presets first, custom presets last, marked with **(custom)**.

## vscode — generate editor settings

```bash
lux vscode <preset> [--stylelint]
lux vscode list
```

built-in presets: `web-vue` `web-react` `electron-vue` `uniapp` `node` `nest` `go`

### Opt-in flags

- `--stylelint` — include Stylelint VSCode settings and extension recommendation

### Control flags

- `--force` — accepted for command consistency, but VSCode presets use merge/write behavior rather than skip/overwrite conflict handling: settings are merged when present, extensions are written or merged depending on built-in/local path.
- `--dry-run` — preview mode
- `--reset` — reset local vscode preset (built-in presets only)

## init — initialize skills or presets

```bash
lux init                  # interactively select AI tool, copy skill files to AI Agent
lux init --preset         # materialize all built-in presets to ~/.lux/preset/ (no cwd writes, no package.json required)
```

## vpn — proxy clipboard helper

```bash
lux vpn cmd       # copy CMD proxy commands
lux vpn pw        # copy PowerShell proxy commands
lux vpn bash      # copy Bash proxy commands
```

## env — proxy env management

```bash
lux set https_proxy="http://127.0.0.1:7890"
lux unset         # clear all config
lux show env      # show stored config
```

## package manager — global override

```bash
lux set lux_package_manager=pnpm    # force pnpm globally (auto, bun, pnpm, yarn, npm)
lux set lux_package_manager=auto     # revert to lockfile detection
lux unset                            # clear all config (reverts to auto)
```

By default lux detects the package manager from lockfile (`bun.lock`, `pnpm-lock.yaml`, `yarn.lock`, `package-lock.json`). Setting `lux_package_manager` overrides this globally — lux will use the configured PM for all projects, with a warning if the project's lockfile doesn't match.

## update — self-update

```bash
lux update        # update to latest
lux update --check
```
